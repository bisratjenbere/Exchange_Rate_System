## Confirmed findings

- Response is a JSON array. Each element is one publication record for one date.
- Top-level fields: `_id`, `id`, `Date`, `published_at`, `ExchangeRate`, `createdAt`, `updatedAt`, `__v`.
- `id == _id` (MongoDB ObjectID string). Stable per publication record. Usable as source_publication_key.
- `Date` field is `YYYY-MM-DD`. One record per date in the default response.
- `ExchangeRate` is an array of 20 currency items per publication record.
- Each ExchangeRate item has its own `id` (ObjectID) — usable as source_record_key.
- Fields per currency item: `cashBuying`, `cashSelling`, `transactionalBuying`, `transactionalSelling`, `currency.CurrencyCode`, `currency.CurrencyName`.
- `?Date=YYYY-MM-DD` filters to exactly one record. Confirmed with `?Date=2021-09-22` → 1 record.
- `_limit=1` returns exactly 1 record. **Confirmed: never send `_limit=1`** (silently truncates to one date).
- Default fetch returns 100 records, oldest first. Date range in fixture: 2021-04-29 to 2021-09-22.
- Zero values: 1205 zero fields across 100 records. Pattern confirms zero = not offered (e.g. INR/KES/SDR/ZAR have cash=0 but transactional>0; SAR/AED have transactional=0 but cash>0).
- No null values in rate fields — zeros are used instead of nulls.
- No weighted average fields in CBE API.
