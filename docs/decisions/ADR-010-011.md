# ADR-010: default_category = transactional for Rammis Bank (Type B1)

Date: 2026-10-12
Status: APPROVED (owner decision required — recorded as KNOWN pending VERIFIED)

## Decision
Set `default_category = transactional` for Rammis Bank (`adapter_key = rammis_api`).

## Evidence
- Live fetch 2026-10-12: API returns a single `buying`/`selling` pair per currency. No category field.
- Official page (rammisbank.et) shows columns labelled "Buying" and "Selling" with no category label.
- Page is JS-rendered; value comparison against API not possible from static fetch.
- Pattern is consistent with all other Ethiopian banks that publish a single unlabeled pair:
  CBE, Dashen, NIB, Omo, Sidama all use `transactional` for their primary buying/selling pair.
- `created_at` is a row-creation timestamp (2025-11-25), not an effective date — ignored.
- Per-currency `effective_date` varies (e.g. CHF = 2026-10-07, USD = 2026-10-12) — rows updated independently.

## Status
KNOWN — one capture, no official-display value comparison performed.
Promote to VERIFIED after: (1) JS-rendered page comparison or (2) 14 days of consistent data
with no contradicting evidence.

## Constraints
- Does not affect identity logic — `source_record_key` + `source_published` date → CONFIRMED.
- Does not affect deduplication.
- Mapping doc updated: category field status → KNOWN (was UNKNOWN).

# ADR-011: default_category = transactional for Wegagen Bank (Type C1 Strapi)

Date: 2026-10-12
Status: APPROVED (owner decision required — recorded as KNOWN pending VERIFIED)

## Decision
Set `default_category = transactional` for Wegagen Bank (`adapter_key = wegagen_api`).
Emit one `transactional` record per currency using `buying`/`selling` fields.
Do not emit a second record for `tra_buying`/`tra_selling` — they are identical values.

## Evidence
- Live fetch 2026-10-12: `buying == tra_buying` and `selling == tra_selling` for all 10 currencies.
  USD: buying=161.7253, tra_buying=161.7253. EUR: buying=159.5012, tra_buying=159.5012.
- Official site (wegagen.com) is a React SPA — rates are JS-rendered. Static fetch returns
  shell HTML only. Value comparison not possible.
- `buying`/`selling` and `tra_buying`/`tra_selling` are duplicates — emitting both would create
  two identical observations per currency, violating the deduplication rule.
- Single unlabeled pair pattern consistent with Rammis, CBE, Dashen (see ADR-010).

## Status
KNOWN — one capture, no official-display value comparison performed.
Promote to VERIFIED after JS-rendered page comparison or 14 days consistent data.

## Constraints
- `raw_excerpt` retains `tra_buying`/`tra_selling` for audit purposes.
- If a future fetch shows `buying != tra_buying`, this decision must be revisited immediately.
  The adapter should emit both pairs with separate categories in that case.
- Mapping doc updated: category field status → KNOWN.
