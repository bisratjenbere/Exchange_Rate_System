# ADR-007: Value-change deduplication for ambiguous-identity observations

Date: 2026-10-10
Status: APPROVED (owner decision)

## Decision
For a given `(source_id, source_currency_code, category)` tuple with `identity_status = ambiguous`:
if the new fetch produces the same `(buying_rate, selling_rate)` as the most recent stored ambiguous
record for that tuple, treat it as a duplicate fetch — no new row. If values differ, store a new
ambiguous record.

## Rationale
~14 banks publish no machine-readable date. Without this rule, every daily fetch produces a new
ambiguous candidate row even when the bank has not changed its rates. The review queue would grow
with identical rows that carry no new information.

## Constraints
- Does not mark observations confirmed or allow them into the trusted view.
- Does not use collection_date_fallback in identity — deduplication is value-based only.
- Ambiguous observations remain excluded from trusted current-rate view until a source-specific
  fallback rule is approved with evidence.
- Implemented as a pipeline step, not in the adapter.

# ADR-008: Per-source default_category config for Type F single-table sources

Date: 2026-10-10
Status: APPROVED (owner decision)

## Decision
Add a `default_category` field to each source entry in source-register.json. Rules:
1. Default is null — adapter emits category=UNKNOWN, routes to review, excluded from trusted view.
2. Owner sets `default_category` after reviewing the official display of that bank.
3. Setting it requires a `default_category_reason` and `default_category_set_date` in the register entry.
4. Adapter reads config at runtime; emits that category instead of UNKNOWN. No code change needed.
5. Mapping doc for that bank is updated to VERIFIED for the category field when set.
6. Only the four approved canonical categories are valid values.

## Affected banks (initially)
DBE, Siinqee, Global, Goh Betoch — and any future single-table source with no category label.

# ADR-009: SSL certificate handling for Hibret, Amhara, BOA

Date: 2026-10-10
Status: APPROVED (owner decision)

## Decision
Use per-source custom CA bundle, not verify=False:
1. Fetch the bank's certificate chain and save as `fixtures/<bank>/ca-bundle.pem`.
2. Pass `verify="fixtures/<bank>/ca-bundle.pem"` to requests.
3. Unexpected certificate change → fetch fails → raw capture with reason `suspicious_data`.
4. Record certificate fingerprint and expiry in source register. Alert 30 days before expiry.

## Temporary fallback
If CA bundle is not yet available, allow `ssl_verify: false` per source as a temporary config flag
with a mandatory `ssl_review_by` date. Adapter logs a WARNING on every fetch when this flag is set.
`ssl_verify: false` is never the permanent state.

## Affected banks
Hibret (hibretbank.com.et), Amhara (amharabank.com), BOA (bankofabyssinia.com).
