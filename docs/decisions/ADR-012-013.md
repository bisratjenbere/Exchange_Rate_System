# ADR-012: default_category = transactional for Type F/G single-pair banks

Date: 2026-10-12
Status: APPROVED (owner decision required — recorded as KNOWN pending VERIFIED)

## Affected sources
ahadu_html, enat_html, dbe_html, siinqee_html, goh_betoch_html (plain pair only), global_html (table 0 only)

## Decision
Set `default_category = transactional` for all of the above.

## Evidence per source

**Ahadu** — page text shows "Buying Rate / Selling Rate" with no category label.
Single pair. Pattern consistent with all other Ethiopian banks with unlabeled pairs.
Date confirmed (source_published). Identity: confirmed.

**Enat** — page text shows "Cash Transaction Weighted" tabs but static HTML only
exposes one set of values. The visible tab in static HTML is the default view.
Mapping doc notes "likely Cash" but the tab label is ambiguous. Using transactional
as the conservative default (same as all other single-pair banks) until JS comparison
is possible. TO VERIFY which tab is default.

**DBE** — table headers: Currency | Code | Buying | Selling. Single pair, no label.
No date → identity ambiguous. Setting category now so data is correctly classified
when a date source is found.

**Siinqee** — table headers: Currency | Buying | Selling. Single pair, no label.
No date → identity ambiguous. Same reasoning as DBE.

**Goh Betoch (plain pair)** — table has both plain buying/selling and weighted average
columns. Plain pair category unresolved. Weighted average already correctly categorised.
Setting plain pair to transactional. No date → identity ambiguous.

**Global (table 0)** — table headers: Currency | Buying | Selling. Single pair.
Table 1 has buying > selling for USD — already flagged as suspicious. Table 0 only
gets default_category. No date → identity ambiguous.

## Status
KNOWN — pattern-based, consistent with CBE/Dashen/NIB/Omo/Sidama/Rammis/Wegagen.
Promote to VERIFIED after official-display comparison per source.

## Constraints
- Does not affect identity. Ambiguous-identity sources remain out of trusted view.
- Ahadu and Enat gain trusted rates immediately (confirmed identity + category now set).
- DBE, Siinqee, Goh Betoch, Global remain out of trusted view until a date source is found.

# ADR-013: Use updatedAt as source_inferred effective_date for ADIB

Date: 2026-10-12
Status: APPROVED (owner decision required — recorded as KNOWN pending VERIFIED)

## Decision
Parse `updatedAt` from each ADIB row as `effective_date` with
`effective_date_basis = source_inferred`.

## Evidence
- Live fetch 2026-10-12: `updatedAt` varies per currency row:
  USD=2026-09-30, EUR=2026-09-30, GBP=2026-09-28, SAR/CHF/AED=2026-09-23.
- Values differ across currencies — this is not a fetch timestamp or a single
  publication date. It is the bank's own record of when each rate was last edited.
- KWD row: updatedAt=2025-08-20, txnBuy=0.0000 — stale/not-offered row.
  normalize_rate already converts 0.0000 → None, so this row is skipped.
- `source_inferred` is the correct basis: the timestamp comes from the source's
  own data, but it is not an explicit "this rate is effective from" publication date.
  It is the closest available proxy.
- `createdAt` is the row creation date (2024-08-06 for most rows) — not useful.
- No explicit effective_date field exists in the API response.

## Identity consequence
`source_inferred` date + `source_record_key` (row id) → `identity_status = derived`.
Derived identity observations ARE included in the trusted view (not excluded like ambiguous).

## Status
KNOWN — one capture. The updatedAt semantics are inferred from value patterns,
not from official documentation.
Promote to VERIFIED after: official-display comparison showing updatedAt matches
the displayed "last updated" date, across at least 3 currencies and 2 fetch dates.

## Constraints
- `updatedAt` is parsed as date only (truncate time component) to avoid
  sub-day identity collisions from minor API edits.
- If a future fetch shows updatedAt changing without a rate change, this decision
  must be revisited — it would mean updatedAt is not a reliable rate-change signal.
- Mapping doc updated: effective_date field status → KNOWN (was unknown).
